# 성능 설계와 측정

## 목적

생활 조작과 영지 시뮬레이션이 서로 끊김을 유발하지 않으면서 주민의 상태가 일관되게 유지되게 한다.

## 처리 전략 — Proposed

- 매 프레임: 플레이어 입력/이동·필요한 표현만.
- 시간 경계: NPC 일정 목적지와 계절 상태 갱신.
- 하루 단위: 생산·소비·재정·프로젝트.
- 월/연 단위: 국가 정책·역사 집계, 확장 시 설계.
- 화면 밖 NPC는 표현/경로 계산을 줄이되 인물 상태는 유지.
- 이벤트 구독 해제와 씬 전환의 노드 수/메모리를 확인.

## 측정과 완료 조건

기준 장비의 OS/CPU/GPU/RAM, 엔진/렌더러/해상도, 주민/건물 수, 시드, 빌드를 함께 기록한다. 프레임 p95, 결산 p95, 초기 로드, 세이브 크기, 메모리/노드 추이를 분리해 측정한다. 평균만으로 순간 멈춤을 숨기지 않는다.

반복 맵/장부 전환, 다년 자동 시뮬레이션, 실제 수동 플레이를 별도로 실행한다. 병목을 재현한 뒤 캐시/배치/주기 조정을 적용하고 같은 조건으로 비교한다. 자료구조 전면 교체나 멀티스레딩부터 도입하지 않는다.
