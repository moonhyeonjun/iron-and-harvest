# Claude Code 개발 지침

이 문서는 이 저장소에서 작업하는 개발 에이전트의 기본 계약이다. 사용자 지시가 우선한다. 현재 프로젝트는 설계 단계이며 게임이 구현되었다고 가정하지 않는다.

## 제품 원칙

- 중세 판타지, 가난한 귀족의 영지에서 제국까지의 성장, 픽셀 아트는 확정 방향이다.
- 생활과 통치가 동일 주민·자원·문제 상태를 공유해야 한다.
- 첫 출시는 작은 영지의 복구·첫 겨울·자립에 집중한다. 전체 제국 기능을 한 번에 만들지 않는다.
- 주민의 삶과 플레이어 행위의 결과가 월드·대사·장부에 나타나게 한다.
- 추가 기능은 핵심 재미 기여와 유지 비용을 먼저 설명한다.

## 작업 전

1. `README.md`, 해당 설계 문서, 최근 주간 기록을 읽는다.
2. `git status`와 관련 코드·데이터·테스트를 확인한다. 아직 Git 저장소가 아니면 상태를 보고하고 Git 사용은 별도 초기화 작업으로 다룬다.
3. 구현할 한 기능, 제외 범위, 변경 파일, 인수 조건을 짧게 명시한다.
4. 기존 사용자 변경을 보존하고 불필요한 전체 리팩터링을 하지 않는다.
5. 필요한 엔진·도구 버전을 실제 확인한다. 설치 또는 실행이 안 되면 그 제한을 명시한다.

## 코드 원칙

- GDScript 타입과 의미 있는 이름을 사용한다. 파일/함수/변수는 snake_case, 클래스는 PascalCase, 상수는 SCREAMING_SNAKE_CASE를 따른다.
- 씬·UI는 표현과 입력, domain은 규칙, application은 작업 흐름, infrastructure는 파일 입출력이다.
- 자원·인력·금화 변경은 명령/서비스로만 실행한다. UI에서 상태를 직접 수정하지 않는다.
- 정의와 런타임 상태를 분리한다. 수치와 콘텐츠 ID를 여러 스크립트에 중복 하드코딩하지 않는다.
- 경로·표시 이름 대신 안정 ID로 저장/참조한다. 삭제된 ID의 저장 호환 정책을 작성한다.
- 생산/세금/NPC 전체 상태를 매 프레임 계산하지 않는다.
- 프레임 시간에 의존하는 경제, 숨은 전역 의존성, 보상 중복, 부분 거래를 금지한다.
- 미래 기능용 빈 모듈이나 범용 프레임워크를 선행 구현하지 않는다.
- 주석은 코드의 반복 설명보다 규칙의 이유와 경계를 기록한다.
- 새 의존성·엔진 변경은 이유·버전·검증·라이선스를 남긴다.

## 테스트 전략

경제·저장·프로젝트 상태 변경은 정상 경로와 최소 하나의 실패/경계 경로를 테스트한다. 단순 문구/레이아웃 변경은 무의미한 단위 테스트를 추가하지 말고 화면을 검증한다.

중요 불변식: 보유량≥예약량≥0, 인물당 직무≤1, 완료 보상≤1회, 결산≤일자당1회, 로드 실패 시 현재 상태 보존. 생산 원료 부족·창고 가득 참·계절 전환·세이브 손상을 커버한다.

프로젝트와 테스트 실행기를 만든 후 사용할 예정 명령(현재는 실행 불가):

```sh
godot --headless --path . --editor --quit
godot --headless --path . --script tests/run_tests.gd
godot --path .
```

설치된 실행 파일명이 다르면 toolchain 문서에 적은 절대 경로로 대체한다. 에디터 import 검사는 실제 게임 플레이 테스트가 아니다. 변경에 해당하는 테스트를 실행하고 UI/상호작용은 실제 창에서 확인한다. 실행하지 못한 검사를 통과로 기록하지 않는다.

## 완료 조건

- 수락 조건에 맞는 기능과 실제 관찰 결과가 있다.
- 관련 테스트가 통과하고 실행 오류가 없다. 미실행이면 미완료 범위를 명시한다.
- 콘텐츠·세이브에 영향이 있으면 문서/마이그레이션/fixture를 갱신한다.
- 변경 내용·실행 명령·결과·알려진 문제·다음 작업을 보고한다.
- 매주 빌드/로그/주간 기록을 남긴다. 기술 부채에는 영향과 처리 시점을 적는다.
- 외부 게시·결제·출시는 사용자의 요청 범위에 따라 처리하며 로컬 구현 완료와 외부 공개 완료를 혼동하지 않는다.

## 문서화

설계 계약은 `docs/design/`, 일정/실행 기록은 `docs/production/`, 양식은 `docs/templates/`에 둔다. 숫자/규칙을 바꾸면 관련 데이터와 문서도 함께 수정한다. 주요 선택은 `docs/design/decisions.md`에 근거·부작용·재검토 조건을 기록한다.

작업 프롬프트는 `docs/production/work-prompts.md`를 사용한다. 다음 기능은 이전 작업의 실제 실행 결과를 확인한 뒤 시작한다.
