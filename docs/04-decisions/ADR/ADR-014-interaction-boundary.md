# ADR-014: 선택·검증·행동의 상호작용 경계

## 상태·날짜

Proposed, 2026-10-31. IH-004 CI 완료 이후 작성한 IH-102 구현 명세다. 작성 당시에는 기능 구현/사용성 검증이 없었다. 이후 구현 결과와 현재 리뷰 상태는 아래 기록을 따른다.

## 배경과 대안

생활 모드에서 같은 키로 물체/주민과 상호작용하되, 이동 컨트롤러가 채집·거래·보상까지 담당하면 확장 시 결합이 커진다. 거리만으로 가장 가까운 대상을 고르면 벽 너머/뒤쪽 대상이 실행될 수 있다. 전역 행동 버스·대형 상태머신은 첫 기능 범위를 넘는다.

## 제안

Player 하위의 별도 Controller가 Area 후보·정면각·가시선으로 대상을 선택하고 입력 시 대상을 캡처한다. 다음 물리 틱에 재검증한 뒤 Target에 동기 요청한다. UI는 값을 표시하고 닫기 의도만 발행한다. 요청/활성 세션 ID로 중복/과거 이벤트를 구분한다.

현재 행동은 설명 읽기이며 보상/재고 변경은 없다. 미래 도메인 명령의 원자성·영속 중복 방지는 해당 기능이 소유한다. 현재 세션 ID를 저장 거래 키로 확대하지 않는다. UI 패널 동안 소유한 이동 게이트만 제어하고 종료·포커스 상실·대상 소멸 시 복구한다.

## 이유·단점

기존 이동을 보존하면서 사용자에게 보이는 선택과 실행 대상을 일치시킨다. Area 업데이트에는 최대 두 물리 틱의 표시 지연을 허용하되 실행 조건은 현재 좌표로 검증한다. 정면각과 거리·우선순위는 조작감 검증이 필요하다. Actor가 여러 명이거나 동시에 여러 모달이 생기면 상위 조율·예약 정책을 추가로 설계해야 한다.

## 영향·검증

[상세 명세](../../02-technical-design/INTERACTION.md)와 [수락 검사](../../03-development/IH-102-ACCEPTANCE.md)에 파일·데이터·API·12개 관문을 정의했다. Claude Code가 구현하며 Codex는 설계·기술 검토를 맡는다. Accepted 전환과 v0.2.0 태그는 구현 검증 이후 별도로 판정한다.

## 구현 검증 결과 (2026-11-01)

Claude Code가 제안 구조대로 구현했고 AC-I01~12 자동 검사와 사용자 GUI 확인을 통과했다([검증 기록](../../03-development/IH-102-VALIDATION.md)). 상태는 **Proposed 유지**다. 구조는 고정 엔진에서 동작했지만 범위·정면각·키·UI의 제품 값과 Accepted 전환은 별도 결정이다.

검토 항목: ① 외부 차단을 `CONTROL_BLOCKED`로 거부하고 neutral 동안 프롬프트를 숨기는 정책. ② 단일 이동 게이트에서 세션 중 외부 잠금을 구분하지 못하는 한계. ③ 시스템 글꼴 fallback에 의존한 한글 표시. ④ 조작감은 단일 사용자의 짧은 확인이며 플레이테스트 표본이 아니다.

## Codex 후속 검토 (2026-11-01)

`29b2ed3`의 추가 재현에서 실행 시 중복 ID 검사 누락과 RESOLVING 중 disable 무시를 확인했다(BUG-003/004). [검토·수락 보완](../../03-development/IH-102-REVIEW.md)을 따른다. IH-102는 review로 재개하며 ADR 상태는 Proposed 유지다. 보상/다중 모달 등의 범위를 넓히지 않고 기존 시작·취소 계약을 보완한다.

수정 결과(2026-11-01): `0332b5a`에서 중복 ID 정책을 선택·실행·활성 검증에 일원화하고, try_begin 중 취소 사유를 기록하도록 수정했다. 회귀와 CI는 [검증 기록](../../03-development/IH-102-VALIDATION.md)에 있다. ADR 상태는 Proposed를 유지하며, Accepted 전환은 별도 판단한다. [PR #12](https://github.com/moonhyeonjun/iron-and-harvest/pull/12)로 develop에 통합했다(IH-102 done).
