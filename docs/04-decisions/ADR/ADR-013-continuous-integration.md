# ADR-013: 단일 CI 관문과 고정 엔진 검증

## 상태·날짜

Accepted, 2026-10-31. IH-004 정상 PR/통합 push 성공, 실패 PR 차단, 보호 GET 확인을 근거로 확정한다. [검증 기록](../../03-development/IH-004-VALIDATION.md) 참조.

## 배경

IH-101은 로컬 자동/수동 검증으로 통합되었다. 다음 기능부터 PR마다 기존 기반·게임 물리 회귀를 같은 명령으로 실행하고 실패가 병합되지 않도록 해야 한다.

## 대안

로컬 전용 검사는 협업 시 누락 가능성이 있다. 여러OS/모든fps 조합은 아직 배포 대상이 확정되지 않았고 첫 CI에 중복 비용이 크다. 외부 Godot 설치 Action은 추가 의존성이다. .godot 캐시는 초기 규모에서 절약보다 상태 오염 위험이 크다.

## 결정

공식 GitHub Actions와 Godot Linux ZIP만 사용하고 Action SHA/엔진 체크섬을 고정한다. 단일 Ubuntu job CI checks에서 Python 저장소 검사와 기존 headless 물리 검사를 실행한다. 저장소의 tools/run_ci.py를 로컬/원격 공통 진입점으로 두며 오류 로그·timeout·완료 마커까지 판정한다.

CI 성공은 GUI/출시 품질을 의미하지 않는다. 읽기 전용 권한, 비밀 없이 PR merge tree 검사, 로그 보존을 적용한다. 원격 보호는 CI checks를 필수로 등록하고 실제 실패 PR로 blocked 동작을 확인한다.

## 영향·단점

문서 PR도 약수분의 검사를 수행하며 네트워크/hosted runner 장애로 실패할 수 있다. 이는 검증 성공으로 간주하지 않고 재시도 원인을 기록한다. macOS GUI 검증은 별도로 필요하다. 모든 소스가 clean인지 확인하므로 로컬 미커밋 변경이 있으면 최종 검사는 실패한다.

상세 계약은 [CI 운영](../../02-technical-design/CI.md)을 따른다. 구현/원격 결과는 IH-004 개발 기록에 남긴다. 게임 기능은 바꾸지 않는다.
