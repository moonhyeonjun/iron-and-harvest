# 코딩 규칙

- GDScript 우선 검토, 엔진의 검증된 버전에 맞는 API만 사용한다. 현재 버전은 TBD다.
- 파일/함수/변수 snake_case, 클래스 PascalCase, 상수 SCREAMING_SNAKE_CASE. 리소스 경로는 소문자와 `/`를 쓴다.
- 매개변수·반환 타입을 명시하고, 자원 수량/금화는 정수로 설계한다. 밸런스 값은 데이터로 분리한다.
- 실패는 호출자가 처리할 수 있는 명시 결과로 반환한다. 부분 거래·중복 보상·숨은 자동 복구를 피한다.
- 주석에는 규칙의 이유와 경계 조건을 적는다. 불필요한 리팩터링과 광범위한 포맷 변경을 하지 않는다.
- 기능 ID·명명·저장 키를 바꾸면 마이그레이션과 참조를 검토한다.
- 새 의존성은 용도·고정 버전·라이선스·제거 비용을 기록한다. 전역 도구 설정을 임의 변경하지 않는다.
- 개인정보/토큰/환경 비밀을 코드·로그·테스트 자료에 넣지 않는다.
- 변경한 기능과 문서가 일치해야 한다. 예정 API/클래스를 구현 완료라고 표기하지 않는다.
