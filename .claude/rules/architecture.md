# 아키텍처 규칙

- 먼저 docs/02-technical-design/TDD.md와 ARCHITECTURE.md 및 해당 작업을 읽는다.
- Godot 루트는 game/, `res://`는 game/ 기준이다. 루트 data/design은 검증용 자료이며 런타임 리소스가 아니다.
- game/scripts는 입력·씬 연결·애플리케이션 흐름, game/systems는 상태와 게임 규칙, game/ui는 화면, game/data는 정의 데이터다.
- 생활과 통치가 동일 상태를 사용한다. 자원 변경은 한 경계에서 검증·적용하며 UI가 상태를 직접 수정하지 않는다.
- 정의/런타임 상태/저장을 구분한다. ID는 안정적이며 번역 표시명·노드 경로를 영속 ID로 사용하지 않는다.
- 일일/월간 처리와 프레임 처리를 분리한다. 모든 주민·건물의 생산을 매 프레임 실행하지 않는다.
- 이벤트는 상태 반영 후 발행하고 중복 완료·재귀 이벤트 폭주를 막는다.
- 미래 Dynasty/Army 등의 빈 매니저를 만들지 않는다. 실제 기능의 최소 의존성만 추가한다.
- 미확정 안을 구현 전제처럼 확정하지 않는다. ADR Proposed/TBD와 현재 코드 동작을 구분한다.
- 구조 변경에는 관련 ADR·경로·테스트·저장 영향 검토를 함께 남긴다.
