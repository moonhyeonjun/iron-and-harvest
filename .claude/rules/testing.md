# 테스트 규칙

- 변경 전에 인수 조건과 관련 테스트를 확인한다. 기능에 맞는 단위·통합·수동 검증을 선택한다.
- 상태 변경은 정상+경계/실패 사례를 검사한다. 자원 음수·예약 초과·이중 인력 배치·중복 완료·중복 결산을 방지한다.
- 저장은 왕복·구버전 migration·손상·실패 시 현재 상태 보존을 검사한다.
- 문서/설정은 정적 검증, 화면/조작은 실제 창의 검증을 수행한다. 무의미한 구현 복제 테스트를 만들지 않는다.
- 루트 tests/는 Python 기반 저장소 검사다. 향후 Godot 테스트는 game/tests/에 두어 res:// 밖 의존을 없앤다.
- 현재 검사 명령은 CONTRIBUTING.md에 있다. 엔진 미설치면 실행 검증을 blocked로 보고한다.
- 실행 명령·환경·종료 코드·관찰·미실행 항목을 WEEKLY_LOG.md에 남긴다.
- 변경된 코드와 관련된 회귀만 우선 실행하고, 실패/새 우려가 없으면 동일 검사를 반복하지 않는다.
- 게임 재미는 수치 테스트와 별도다. 플레이테스트 표본과 관찰을 측정값으로 남긴다.
